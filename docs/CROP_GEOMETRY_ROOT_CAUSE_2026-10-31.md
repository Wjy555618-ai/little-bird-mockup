# 裁切、孔径与最终像素：当前根因和不变量（2026-10-31）

## 旧结论作废

此前只证明“控制框与中间投影对象相等”，没有证明拖动单边时另一轴不变，也没有证明画布外框、裁切框、物理孔径和最终像素使用同一几何。用户截图已经证明旧验收不足；旧构建和旧通过计数不得继续作为当前结论。

## 最高错误层的根因

1. 单边拖动先改变一条边，随后又调用通用边界约束；通用约束为了把框塞回孔径会统一缩放宽和高，导致拖右边时上下也变化。
2. 键盘缩放和鼠标拖动分别维护两套计算，行为可以互相矛盾。
3. 裁切框错误复用设备物理孔径圆角，外层 `.canvas-wrap` 又额外添加固定圆角，形成与真实画布无关的第二套边界。
4. 控制点用负 inset 扩大命中区，相邻控制点在小尺寸设备上会重叠，拖一个点可能被另一个点抢占。

## 当前唯一几何模型

- `screen.aperture.quad`：设备物理开口，只负责最终遮罩和边界约束。
- `contentFrame`：用户可编辑的矩形/四边形；裁切框、命中区和投影都从它一次计算。
- `imageFrame`：来源图相对内容框的变换，始终覆盖内容框。
- `resizeFrameWithinBounds()`：鼠标和键盘共同使用的单一缩放入口。
- 拖左/右边只允许修改 `x` 和 `width`，固定 `y`、`height` 与对边；拖上/下边只允许修改 `y` 和 `height`，固定 `x`、`width` 与对边。
- 当指针要求越过物理孔径时，沿当前拖动轴二分回退到最后一个合法位置；不得借机缩放另一轴。
- 四个角点才允许双轴按比例缩放。
- 裁切框使用精确投影路径，不添加设备圆角；设备圆角只在最终孔径遮罩中生效。
- 外层预览画布保持真实方形边界，不添加固定 CSS 圆角。

## 防回归门禁

`tests/plugin.test.mjs` 对四条边、两个方向和越界输入逐项断言：

- 非拖动轴的坐标与尺寸严格不变；
- 对边严格不变；
- 结果始终在物理孔径内；
- 鼠标和键盘调用同一约束函数；
- 裁切框不得调用物理圆角路径；
- `.canvas-wrap` 为方形边界；
- 控制点不得用伪元素制造重叠命中区。

最终像素测试仍使用正式 `renderComposite()`，要求投影控制框外的高对比用户像素为零。
