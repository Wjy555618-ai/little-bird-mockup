# 样机卡片悬停：根因、唯一模型与防回归门禁（2026-10-31）

## 最终交互契约

决定人要求的是“每次鼠标进入样机卡片时，随机选择左/右方向并轻微旋转；同一次停留期间保持不变；移出复位；再次进入才重新采样；不出现悬停描边”。这是当前唯一有效规则。

## 真实根因

旧实现把 `transform: rotate(...)` 直接用在 `.asset-card` 上。`.asset-card` 同时又是指针命中区，旋转后命中边界跟着变化，指针靠近边缘时会在“进入—移出—再进入”之间形成反馈闭环。错误的后续修正又删除了用户要求的旋转，改成悬停描边/背景/阴影/亮度，这虽避免了命中区变形，但改错了产品行为。

因此根因不是“随机旋转本身不可行”，而是“可见变换和指针命中几何使用了同一层”。

## 当前唯一实现模型

- `.asset-card` 是固定尺寸、固定位置的命中区，永不做 `transform`。
- `.asset-card-visual` 是内部纯视觉层，`pointer-events: none`；只有这一层可旋转。
- 角度在每次真正跨越卡片边界时采样一次：随机方向，幅度 `1.8°–2.7°`。
- 卡片内部的子节点切换不算重新进入；停留期间不读取指针位置、不跟随、不重算。
- 移出时归零并删除该次状态；再次进入才会得到新的方向和角度。
- 悬停不增加描边、背景、阴影或亮度。选中描边和键盘 `:focus-visible` 是独立语义，不得与悬停混用。
- `prefers-reduced-motion: reduce` 下不启动旋转，并清理已有悬停状态。
- 悬停不修改样机选择、最近使用、预览渲染或素材状态。

## 可执行防回归门禁

`tests/plugin.test.mjs` 和 `plugin/asset-card-hover.js` 共同锁定：

1. 外层 `.asset-card` 没有几何变换，内层 `.asset-card-visual` 不接收指针事件；
2. 单次进入只消耗两次随机值（方向+幅度），停留期间再次调用也不重采样；
3. 移出必须归零并清理状态，再次进入必须重新采样；
4. 卡片内部跨子节点不能触发移出/重进入；
5. 不存在悬停描边规则，不存在悬停 `pointermove` 随机化；
6. 卡片入场动画只改透明度，不移动命中区。
