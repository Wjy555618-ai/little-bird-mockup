# 样机屏幕接缝与彩色角块：当前根因和不变量

日期：2026-10-31
当前目录规范：schema v5 / `static-screen-v5`

## 旧方案全部作废

2026-10-30 的绿幕、`chroma-edge`、色键软边扫描和用户像素欠压方案已经删除，不能再作为上传门禁、接缝修复或当前证据。它们会把素材颜色当成几何，并可能让用户像素越过控制框。

## 用户截图中紫色角块的真实根因

问题不是 Figma 选区，也不是用户导入的白色画面。旧迁移脚本把一张蓝紫色“示例界面”直接烘焙进完整底图，并按屏幕四边形整块绘制；运行时又使用带圆角的物理孔径裁剪用户画面。两者边界不同，所以用户画面的圆角外仍会露出烘焙底图的紫色三角。

同一张蓝紫示例界面还由运行时默认画面和缩略图脚本重复生成，因此即使修一处，其他入口仍会复现。旧 QA 只检查“不是绿幕”，没有检查屏幕内容来自哪里，因而把未经授权的合成界面和紫色角块一起放行。

## 当前统一方案

1. 完整底图只能声明两种屏幕展示来源：
   - `neutral-off`：中性关屏，屏幕区域平均色度必须不高于政策上限；
   - `reference-bound`：彩色内容必须绑定与 provenance 相同的准确参考 SHA-256。
2. 插件、共享渲染器和缩略图脚本不再生成默认界面；没有用户画面时显示完整底图自己的关屏状态。
3. 用户画面只通过显式 `screen.aperture.quad` 和物理圆角遮罩投影；裁切框不复用该圆角。
4. 修订底图以 3px 中性关屏保护区覆盖旧烘焙内容的边缘采样，保护区属于底图，不是用户内容扩张。
5. `screen.presentation` 缺失、模式未知、`neutral-off` 色度超限、或 `reference-bound` 摘要错配时，候选、目录检查、QA 和发布全部失败关闭。

## 当前状态边界

五个 r3 修订候选已进入 testing，均为 `neutral-off`，真实 Figma+EX 预览中显示中性关屏，手机底部不再出现紫色角块，也没有蓝紫示例界面。它们尚未获得决定人的视觉批准，因此 production r2 保持不变；当前全量发布门禁故意拒绝旧 production r2 缺失的新来源声明。这是阻止旧问题继续发布的安全结果，不得通过伪造元数据绕过。
