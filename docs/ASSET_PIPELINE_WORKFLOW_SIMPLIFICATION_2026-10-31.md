# 样机流水线用户审批纠正

记录日期：2026-10-31（Asia/Shanghai）

决定人：Wang Zhentao

## 问题证据

旧流程把同一个本地样机修复拆成了基线、构建、视觉候选、技术 QA、正式入库和最终验收等多次人工确认。决定人已经承担了远超原始承诺的审批次数，且技术 QA 因缺少前置视觉批准而不能执行，造成人工等待和反复指纹刷新。

决定人明确要求：

> “怎么那么复杂呢？你是不是把流程拆得很细很细，做得非常重？”

> “你不是说只让我确认两三个点吗，你现在一直让我确认！”

> “改！彻底修改你当前问题！”

## 纠正后的权限边界

1. 人类仍对新参考图的权利与创作委托负责；这两项在提交新参考图时合并记录，不得拆成多次确认。
2. 候选创建后，自动检查、几何校验、四种测试图、技术 QA、插件构建和真实 Figma 宿主回归都由执行系统先完成，不得要求人类先批准内部基线、构建指纹或候选指纹才能继续。
3. 人类只对已经完成技术 QA 的最终审阅包做一次决定：“通过并进入本地正式库”或“不通过”。
4. 一次最终决定可以覆盖一个明确的批次；批次必须绑定每个 `assetId + revision + itemSha256 + qaReportSha256`、当前插件构建指纹和批次指纹。
5. 指纹由系统生成和校验，不是人类需要理解或分别批准的工程步骤。
6. 只有产品目标、外部发布权限、参考图或最终审阅批次发生实质变化时，才再请求人类决定。

## 新的唯一主路径

`REQUEST_AUTHORIZED → REFERENCE_RECORDED → CANDIDATE_READY → TESTING → QA_PASSED → FINAL_APPROVED → PROMOTED`

`CANDIDATE_READY` 后必须自动进入 `TESTING`；禁止恢复“先人工视觉批准、再技术 QA”的前置阻塞。

## 不变的安全门禁

- 没有新参考图权利和创作委托时，不能生成新候选。
- 技术 QA 失败时，不能出现最终审阅包。
- 最终批次指纹或任一素材/QA/构建摘要漂移时，人类决定自动失效。
- 未获得最终批次决定时，不能提升正式库。
- 本资产流水线不自行授权外部发布；唯一阶段零 Netlify 试运行必须由远程目录合同的精确站点、白名单和逐次人工授权管理。GitHub、Figma 社区和其他外部发布仍禁止。
