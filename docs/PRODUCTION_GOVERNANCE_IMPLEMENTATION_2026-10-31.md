# 生产级治理实施回执｜2026-10-31

## 结论

本轮完成了生产治理第一阶段，不再允许把开发构建通过误称为可发布。当前开发版本满足 `DEVELOPMENT_READY` 的本地工程证据要求，但生产发布仍被真实外部条件阻断。

## 已实施

- 建立人类可读开发合同和 17 项机器阻断门禁，分为 `DEVELOPMENT_READY`、`PUBLISH_READY`、`MATURE_PRODUCT`、`SUCCESSFUL_PRODUCT` 四级；高级声明继承全部低级门禁。
- 最终漂移复核修正了一个合同层错误：生产门禁 `G-020` 不再错误地计入 `DEVELOPMENT_READY`，但继续作为 `PUBLISH_READY` 及全部更高声明的必要门禁。
- 新增不可缩减的元合同：17个门禁、四级精确门禁集合、阶段、自动命令、人工场景、政策字段、比例边界和证据路径全部使用确定性白名单校验；删除门禁、弱化高级声明、替换命令、增加政策外场景或让证据路径逃逸都会失败。
- 建立 `config/plugin.config.json` 单一配置源；UI、main code 和 manifest 均由模板生成，不再分别维护版本、缓存键、目录地址或插件 ID。
- 开发与生产构建显式分离。生产构建拒绝 IP、localhost、保留测试顶级域、`example.com/.net/.org` 及其子域、空/全零 ID、错误目录环境和开发网络权限。
- 构建指纹覆盖 UI 模板、样式、共享渲染器、共享目录契约、main code、manifest、单一配置、package、锁文件、构建脚本、PDF 主包和 worker。
- 运行时目录契约要求 environment、schema、renderer、minimumPluginVersion、分类/ID、revision、状态、来源、完整性摘要和正式 QA 元数据全部匹配。
- 基底图、缩略图和可选图层在进入缓存前计算 SHA-256；实际文件与目录摘要不同即拒绝渲染。
- 远程高清素材缓存改为最多 8 项 LRU，后台只预取相邻最多 3 项；移除全目录高清预加载。
- 资源上限不再由源码字符串测试证明：共享LRU机制实际执行500个唯一资源连续写入、缓存命中刷新、异步失败隔离和500项目录最近预取测试。
- 离线目录必须来自当前构建的同一 URL，且缓存时间不超过 168 小时。
- 目录最多500项、JSON最多2 MiB、单个远程素材最多32 MiB；流式读取一旦越界立即取消，不能先把异常大响应完整装入内存。目录还会拒绝绝对URL、协议URL、查询、锚点、反斜杠和父目录穿越路径。
- 修复搜索框语义：清除按钮不再嵌套于 label，输入框拥有独立“搜索样机”名称；统一提高弱文字对比度并强化焦点可见性。
- 新增 GitHub Actions 本地配置：只读最小权限，第三方 Action 固定到完整40位提交SHA；提交/PR与每周计划执行开发合同和依赖审计，版本标签生成并保留90天的REL发布包；Dependabot每周检查Action与npm依赖。CI验真按任务结构而非全局字符串工作，命令放错任务、恒假条件、静默忽略失败、额外任务或未知Action都会失败。由于当前仓库没有 origin，本轮没有远程运行证据。
- 生产发布不再只做临时检查：`release:package` 要求版本标签已发布到origin且解析到当前提交，并在构建结束后复查HEAD和工作区；随后原子生成不可覆盖的 `dist/plugin`，其中包含发布来源、合同ID与合同字节摘要、测量政策、目录版本/摘要和制品摘要 provenance；临时包和最终原子重命名前的暂存包都会重新验真。若生产URL已是可发布候选，门禁会以10秒超时、禁止重定向、2MiB流式上限和JSON内容类型读取远程目录，并要求远端字节与本地正式manifest完全一致。
- 建立 `quality/measurement-policy.json` V4 预注册政策、fail-closed证据草稿和 `scripts/verify-evidence.mjs`：人工证据必须绑定同一REL指纹、版本标签提交、真实制品摘要、合同字节摘要、目录版本/摘要和政策摘要；覆盖全部场景断言、原始附件、时间和环境，并满足预先固定的性能、无障碍、回滚、外测与成功指标阈值。附件必须提交字节数与SHA-256；比率由安全整数分子/分母机器重算且必须有预注册上下界。工具会拒绝错误合同路径、政策登记前测量、未来/倒置时间、伪造比率以及通过符号链接逃逸证据目录的附件。
- 正式目录现在会在变更前自动保存版本快照，相同revision文件禁止以不同字节覆盖，manifest采用原子替换；回滚命令默认只演练，只有显式 `--apply` 才会恢复旧内容，并强制发布为新的单调目录版本。
- Figma多选读取限制为最多50层、逐层串行导出和累计80MiB，避免无界 `Promise.all` 内存尖峰；本地文件同样由单一配置限制为80MiB。

## 当前被门禁正确阻断

`pnpm release:check` 当前输出 `RELEASE BLOCKED`，原因是：

1. 生产目录仍为保留测试域名；
2. 正式 Figma plugin ID 尚未提供；
3. 工作区包含未提交改动；
4. 仓库没有非本地、非保留域名的 origin 远端；
5. 当前提交没有 `v0.1.0` 标签。

这些是事实阻断，不应通过降低门禁解决。绑定真实域名和 ID 后，仍需完成合同 G-100 至 G-150 的发布/成熟证据，以及 G-200、G-210 的外部用户成功证据。
